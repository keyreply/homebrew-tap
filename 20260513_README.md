# keyreply/homebrew-tap

Homebrew tap for KeyReply internal CLI tools.

## Install

```bash
brew tap keyreply/tap
brew install kira
```

## Upgrade

```bash
brew upgrade kira
```

## Formulas

| Name   | Source                                                                                  | Branch                  |
| ------ | --------------------------------------------------------------------------------------- | ----------------------- |
| `kira` | [keyreply/kira-cloudflare](https://github.com/keyreply/kira-cloudflare) `cli/` (private) | `codex/convex-rewrite`  |

## Distribution model

The upstream source (`keyreply/kira-cloudflare`) is private. Pre-compiled
single-file binaries are produced with `bun build --compile` from `cli/` and
attached as release assets on this tap repository. The formula downloads the
binary directly, so end users do not need access to the private source repo.

Supported platforms (initial release):

- `darwin-arm64` (Apple Silicon, macOS)

To add `darwin-x86_64` or Linux, build on the respective platform and attach
additional assets to the release, then extend `Formula/kira.rb` with matching
`on_intel` / `on_linux` blocks.

## Releasing a new version

1. Check out the upstream branch you want to ship from:
   ```bash
   git -C kira-cloudflare worktree add /tmp/kira-build origin/codex/convex-rewrite
   cd /tmp/kira-build/cli
   bun install --frozen-lockfile
   bun build src/index.ts --compile --target=bun --outfile kira
   ```
2. Package the binary:
   ```bash
   tar -czf "kira-${VERSION}-darwin-arm64.tar.gz" kira
   shasum -a 256 "kira-${VERSION}-darwin-arm64.tar.gz"
   ```
3. Create a GitHub release on this repo and attach the tarball:
   ```bash
   gh release create "v${VERSION}" \
     --repo keyreply/homebrew-tap \
     --title "kira v${VERSION}" \
     --notes "kira CLI v${VERSION} (codex/convex-rewrite)" \
     "kira-${VERSION}-darwin-arm64.tar.gz"
   ```
4. Bump `version` and the `sha256` in `Formula/kira.rb`, commit, push.
5. Users run `brew update && brew upgrade kira`.

## Known caveats

- `cli/src/index.ts::getCliVersion()` reads `package.json` at runtime via
  `readFileSync`, which is incompatible with `bun build --compile`. The release
  workflow currently patches that function to return a hard-coded version
  before compiling. A proper upstream fix would inline the version at build
  time (e.g. via `--define`).
